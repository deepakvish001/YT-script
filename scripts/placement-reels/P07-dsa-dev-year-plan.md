# P07 · सुबह DSA, रात को Dev: दोनों में average?
**Series:** प्लेसमेंट का सच · **लंबाई:** करीब 74 सेकंड · **Keyword:** ROADMAP · **एक सीख:** हर दिन दोनों को आधा-आधा देने से अच्छा है कि हर phase में एक चीज़ captain हो और दूसरी बस ज़िंदा रहे।

## 🎙️ वॉइसओवर
तुम्हारा routine है सुबह LeetCode, रात को React, और बीच का time guilt के लिए, और छह महीने बाद DSA वाले तुम्हें developer समझते हैं और developers तुम्हें DSA वाला। इसकी एक वजह है task switching cost, यानी दिमाग जब एक काम से दूसरे पर जाता है, तो gear बदलने का टैक्स लगता है। Sophie Leroy की research इसमें attention residue दिखाती है, यानी पिछले अधूरे काम का कुछ ध्यान अटका रह जाता है, जैसे React खोलते ही दिमाग सुबह वाले graph पर लौट जाता है। और जब दोनों रोज़ थोड़े थोड़े हों, तो किसी को वो लंबी sitting नहीं मिलती जिसमें मुश्किल चीज़ बैठती है। इसलिए मेरा Captain plan अपनाओ, जिसमें हर phase का captain अलग है। पहले दो साल DSA और basics captain हैं, करीब 70 percent, और development 30 percent। तीसरे साल captain बदलो, यानी 70 से 80 percent project और internship, और DSA हफ्ते के कुछ problems से ज़िंदा रखो। फिर तीसरे साल की summer से placement तक DSA और interview prep दोबारा captain बनें, करीब 80 percent, और बाकी में project polish करो। ये rule of thumb है, college calendar के हिसाब से adjust कर लेना। Comment में ROADMAP लिखो, मैं तुम्हें चारों साल का roadmap DM कर दूँगा, और follow कर लो।

## 📄 Cheat sheet (comment → DM)
**नाम:** Captain plan: 4 साल का DSA + Dev roadmap · **Keyword:** ROADMAP
- **पहला साल (captain: basics):** एक language पक्की (C++ / Java / Python), logic building, arrays, strings, recursion की शुरुआत; Git + GitHub account; CGPA को आम cutoffs से ऊपर रखो, बाद में यही दरवाज़े खोलता है।
- **दूसरा साल (captain: DSA, करीब 70%):** linked list, stack, queue, hashing, binary search, trees, graphs (BFS / DFS), DP की शुरुआत, topic-wise practice। **Dev (करीब 30%):** HTML / CSS / JavaScript या अपना चुना stack, 1–2 छोटे projects, deploy करना सीखो।
- **तीसरा साल (captain: development, करीब 70–80%):** एक बड़ा project (login, database, API, deploy, README), hackathon या open source, internship applications। **DSA (करीब 20–30%):** हफ्ते में कुछ problems + एक contest, पुराने patterns revise।
- **तीसरे साल का ध्यान:** कई colleges में internship drives तीसरे साल में ही होती हैं और उनका OA DSA वाला होता है; तुम्हारे college में ऐसा है तो उन महीनों से पहले DSA का हिस्सा कुछ हफ्तों के लिए बढ़ा लो।
- **तीसरे साल की summer → placement (captain: DSA + interview, करीब 80%):** patterns revise, timed practice, mock interviews, OS / DBMS / CN / OOP, aptitude (जहाँ test हो)। **Project polish (करीब 20%):** README, live demo link, अपने design decisions बोलकर समझा पाना।
- **हफ्ते का ढांचा:** captain वाले काम को लंबे, बिना phone वाले blocks दो; vice-captain वाले काम को हफ्ते में 1–2 fixed slots; एक दिन revision + आराम।
- **Phase बदलने का signal:** DSA में किसी topic के medium सवाल बिना hint बनने लगें; dev में कोई दूसरा इंसान तुम्हारा project use कर सके और तुम उसका design समझा सको।
- **Interleaving ≠ इधर-उधर कूदना:** DSA के अंदर अलग-अलग topics mix करके practice करना फायदेमंद हो सकता है; दिक्कत रोज़ दो बिल्कुल अलग tracks को आधा-आधा देने में है।
- **Numbers को कानून मत बनाओ:** 70 / 30 एक rule of thumb है; अपने college का placement calendar, अपनी कमज़ोरी और target role देखकर 10–20% ऊपर-नीचे करो।

## ✅ ध्यान रखो / सोर्स
- **मत बोलो:** "Big Tech funnel", "research कहती है 70/30 सबसे best split है", "DSA और dev साथ करना बेवकूफी है"। Split एक rule of thumb है, research का number नहीं; VO में ये साफ़ बोला है।
- Task switching cost lab में छोटे-छोटे, जल्दी-जल्दी switches पर measure हुआ है (Rubinstein et al. 2001; Monsell 2003), और attention residue (Leroy 2009) एक task से तुरंत दूसरे पर जाने के बाद के performance पर। "Research कहती है घंटों बाद तक residue रहता है" मत बोलो; VO की "React खोलते ही graph पर लौट जाना" वाली line एक relatable उदाहरण है।
- Interleaving (एक ही subject के problem types mix करना) फायदेमंद पाया गया है (Rohrer & Taylor 2007); इस reel का message "mixing हमेशा बुरी है" नहीं है।
- Placement season और internship drives का समय हर college में अलग होता है; "हर college में placement 7th semester में" जैसा absolute दावा मत करो।
- Framework का नाम अपना है: **Captain plan**।
